# LLM Usage Metering & Billing Engine

This is a backend service that meters API and AI token usage per customer, enforces monthly plan quotas, calculates costs using real-world AI token pricing rules (cached input tokens, reasoning tokens), and integrates with Stripe in test mode to handle subscription upgrades through signature-verified, deduplicated webhooks.

## Plans

| Plan | API calls / month | AI tokens / month | Price |
|------|--------------------|--------------------|-------|
| Free | 1,000              | 100,000            | $0    |
| Pro  | 50,000             | 5,000,000          | $29/month |

## Setup

1. Clone this repository.
2. Create a virtual environment and activate it:
   ​```
   python -m venv venv
   .\venv\Scripts\Activate.ps1
   ​```
3. Install dependencies:
   ​```
   pip install -r requirements.txt
   ​```
4. Copy `.env.example` to `.env`, and fill in your own Stripe test-mode secret key and webhook secret:
   ​```
   STRIPE_SECRET_KEY=sk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...
   ​```
   The webhook secret is generated by running `stripe listen --forward-to localhost:8000/webhooks/stripe` (requires the Stripe CLI, logged into your own Stripe account in test mode).

## Seed the database

​```
python -m app.seed
​```

This creates `billing.db` (SQLite) and seeds the Free and Pro plans.

## Run

​```
uvicorn app.main:app --reload
​```

The API is available at `http://localhost:8000`.

To test Stripe webhooks locally, in a separate terminal, run:
​```
stripe listen --forward-to localhost:8000/webhooks/stripe
​```

## API reference

### `POST /tenants`
Creates a new tenant on the Free plan. Returns the tenant's id, name, generated API key, and current plan.

### `POST /generate`
Records a billable usage event. Requires an `X-API-Key` header identifying the tenant.

Request body for an API call:
​```json
{
  "usage_type": "api_call",
  "quantity": 1,
  "idempotency_key": "unique-key-here"
}
​```

Request body for AI tokens:
​```json
{
  "usage_type": "ai_tokens",
  "idempotency_key": "unique-key-here",
  "input_tokens": 1000,
  "cached_input_tokens": 2000,
  "output_tokens": 500,
  "reasoning_tokens": 300
}
​```

Sending the same `idempotency_key` twice returns the original result instead of recording a new event. A request that would push the tenant over their monthly quota is rejected with a 429 status code.

### `GET /usage`
Returns the calling tenant's current month usage, plan limits, and total cost in cents. Requires an `X-API-Key` header.

### `POST /checkout`
Creates a Stripe Checkout session for upgrading the tenant to the Pro plan. Requires an `X-API-Key` header. Returns a `checkout_url` to complete payment with a Stripe test card.

### `POST /webhooks/stripe`
Receives Stripe webhook events. Verifies the signature (rejecting forged requests with a 400), ignores already-processed events, and updates the tenant's plan and subscription status when a checkout completes.

## Limitations

This system does not support overage billing, mid-cycle plan proration, or invoicing. When a tenant exceeds their quota, the request is simply rejected with a 429 response, they are not charged extra, and no partial credit is calculated for a mid-month upgrade.

There is no authentication beyond a per-tenant API key, there is no way for a tenant to downgrade from Pro back to Free through the API (this would need to be handled via a `customer.subscription.deleted` webhook, which updates the Subscription record's status but does not currently revert the tenant's plan automatically).

The database is SQLite, a single file, suitable for local development and evaluation, not designed for concurrent production traffic.
